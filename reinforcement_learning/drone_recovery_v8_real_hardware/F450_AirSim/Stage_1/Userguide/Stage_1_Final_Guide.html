1. How Stage 1 works

Reinforcement learning from scratch crashes the drone within the first few steps, because a random network has no idea how to fly. That's the cold start problem. Stage 1 avoids it: a simple teacher flies the drone, and a neural network learns to copy the teacher's commands. This is behavioural cloning, and the result is a network that can already hover before reinforcement learning starts in Stage 2.

A learner driver sits next to an instructor and writes down, at every moment, where the car was and what the instructor did with the wheel. After 60,000 notes, the learner can drive the same road alone. Stage 2 then takes this learner onto a windy road.
Stage 1 in one picture. The teacher looks at how far the drone is from the target and commands a velocity back towards it. The network sees the same 13 numbers and learns to output the same command.

1b. Stage 1 and Stage 2

Stage 1 → Stage 2 is a real weight transfer. Stage 2 PPO is born as an exact copy of this network (the check prints a maximum action difference of 0.0) and then improves it in wind. That's why every Stage 2 training episode survived from the very start. Stage 3 is different: it's trained on its own and combined with Stage 2 at flight time (see the Stage 2 guide, section 1b).

3. How to run (in order)

Before any flying script: start AirSim, then ArduPilot SITL in GPS mode (your usual launch), wait until it's ready, then run the script from the Stage_1\ folder. Steps 3.2 and 3.5 need no simulator.
3.0Start AirSim + ArduPilot SITL (WSL)≈ 2 min · before every flying script

Order: AirSim (Windows) → SITL (WSL) → script (PowerShell). Keep both windows open while the script runs.

1. Windows: start AirSim (your WindowsNoEditor build) and wait until the drone is shown.

2. WSL (Ubuntu terminal): start SITL from the GPS folder ~/sitl_gps, not from ~/ardupilot.

Why the folder matters: SITL saves its parameters (eeprom.bin) in the folder you start it from. ~/ardupilot holds the optical-flow setup; ~/sitl_gps holds the GPS setup used for Stages 1–3. Like two save files in a game: the folder decides which drone you load.

First time only (creates the GPS folder; SITL starts there with default parameters):

mkdir ~/sitl_gps

Every time:

cd ~/sitl_gps
sim_vehicle.py -v ArduCopter -f airsim-copter --console --map --sim-address=172.28.0.1 --out=127.0.0.1:14550

Restart AirSim after editing settings.json.

5. Findings and discussion

#FindingEvidence
F1Behavioural cloning solves the cold start. The network flies every target alone, with no reward signal at all.10/10 success and settled, end error 0.038 m
F2The copy matches the teacher's position control.RMSE 0.348 vs 0.344 m; 98.9% transfer efficiency; no significant difference (p = 0.30)
F3The one consistent difference is a small final offset.end error 0.036 vs 0.013 m, 10/10 episodes (p = 0.002), still 8× inside the 0.3 m limit
F4The network copied the teacher's behaviour, not just its score.command histograms overlap; vd spread identical (0.091 m/s)
F5Hand-over to reinforcement learning is exact.max action difference 0.0 inside PPO; Stage 2 had zero crashes in training
F6Results are reproducible across sessions.17 vs 23 Oct within 0.007 m per episode

Why the small final offset (F3)?

  • Near the target, the teacher's commands are tiny (gain × a few centimetres). The network learns a regression of all commands, and a small, nearly constant bias of a few mm/s matters most where the commands are smallest. So the copy stops a few centimetres early. Larger, faster corrections are copied almost perfectly, which is why the RMSE is the same.
  • This is a known limit of pure imitation: a student can't be more precise than the examples, and small errors aren't corrected because no reward pushes it closer. That's exactly what Stage 2 adds. PPO is rewarded for distance at every step, and Stage 2 then improved the hover to 0.11 m average horizontal distance even in gusts.
