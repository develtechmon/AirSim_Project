1. How Stage 2 works

Stage 1 taught the network to hover by copying a teacher in calm air. Stage 2 takes that same network and lets it practise in gusty wind with reinforcement learning (PPO), so it learns what the teacher never showed it: how to get back to the target quickly after a gust.

Stage 1 is a learner driver who passed the test on a quiet road by copying the instructor. Stage 2 is the same driver practising on a windy coastal road with no instructor. They start with everything they already know (warm start), and every second spent off the lane costs points, so they learn to correct faster.
Stage 2's job: hold a fixed point in the air while gusts push the drone away. The network only chooses velocity commands; ArduPilot's own inner loops still fly the motors.

One training episode (25 s)

StepWhat happensWhy
1. ResetWind off. The teacher flies the drone to a random start within ±1 m (±0.3 m height) of the target.Every episode starts slightly off target, so the network must also learn to approach.
2. Wind onA gust of random direction and strength 0–20 (vertical part ×0.3); a new gust every 1–3 s.Changing wind, like real outdoor air.
3. Fly500 steps at 20 Hz. Each step: read 13 inputs → network → velocity N/E/D (sent limit 2 m/s sideways, 1 m/s vertical).Same interface as Stage 1, so the weights fit exactly.
4. Scorereward = +1 − distance − 0.1·speed − 0.01·|action|²; −50 and stop if > 4 m away, height < 0.5 m or > 5 m, or tilt > 60°.Every metre off target costs points every step, so getting back fast pays.
5. LearnEvery 2048 steps PPO updates the network (a few seconds). Meanwhile the safety pilot turns the wind off and holds the drone; the interrupted episode is marked update_pause and not counted.The drone is never left without commands.

1b. Stage 2 and Stage 3: how they fit together

Read this carefully. Stage 1 → Stage 2 is a real weight transfer. Stage 2 → Stage 3 is not. Stage 3 is trained on its own, starting from its own teacher (attitude rule → BC → PPO). The two networks are combined at flight time by switching between them.
Stage 2 networkStage 3 network
Jobhold position, reject gustsrecover from impact, flip or spin
Commandsvelocity N/E/D (GUIDED)roll, pitch, thrust (attitude target)
Inputsoffset, velocity, quaternion, ratesdown vector, rates, height change, speeds, previous action
Rate20 Hz50 Hz
Starts fromStage 1 weights (transfer)its own BC network (standalone)

Inputs, outputs and loop rates are all different, so Stage 2 weights cannot be poured into Stage 3. Copying them would also not keep the gust skill. Instead, both run on the drone and hand over control to each other:

Normal flight Stage 2 network holds position and rejects gusts
▼ impact detected: ‖ω‖ > 3 rad/s or tilt > 60°
Recovery Stage 3 network stops the spin, levels the drone and saves height
▼ calm again: ω < 1.2 rad/s, tilt < 30°, falling < 1 m/s
Back to normal flight Stage 2 network flies back to the target
A car with two specialists: a cruise-control system for wind on the motorway (Stage 2) and an anti-skid system for a spin-out (Stage 3). You don't merge them into one brain; the car switches to the right one at the right moment.

Order: AirSim (Windows) → SITL (WSL) → script (PowerShell). Keep both windows open while the script runs.

1. Windows: start AirSim (your WindowsNoEditor build) and wait until the drone is shown.

2. WSL (Ubuntu terminal): start SITL from the GPS folder ~/sitl_gps, not from ~/ardupilot.

Why the folder matters: SITL saves its parameters (eeprom.bin) in the folder you start it from. ~/ardupilot holds the optical-flow setup; ~/sitl_gps holds the GPS setup used for Stages 1–3. Like two save files in a game: the folder decides which drone you load.

4.3 Every episode, not just the average

An average can hide a few lucky episodes. Because every controller flew the same 10 gust sequences, each episode is a fair head-to-head.

Gust RMSE per episode (m)
episode 1–10 = seeds 2000–2009 · lower is better · PPO is lowest in all 10
Four drivers race on the same 10 tracks with the same weather. If one driver wins all 10 races, that is not luck. With 10 pairs, a 10-out-of-10 sweep gives p = 0.002, the strongest result a 10-episode test can give.

In a steady push, every controller settles at about the same small offset. ArduPilot's inner velocity loop removes a steady push for all of them. PPO trained on changing wind, and that is where it is better. The honest claim is "better gust rejection", not "better in all wind".

Why PPO recovers faster

  • The reward pays for every second near the target. Distance is penalised every step, so a quick return is worth more than a gentle one. The teacher it started from never had that pressure.
  • It reads the drone's tilt and turn rates (quaternion and p, q, r are inputs). A gust tilts the drone before it has moved far, so the network can start correcting early. The PID teacher only looks at position and velocity, and only proportionally.
  • Stock ArduPilot is tuned to be smooth. Its position controller limits acceleration and jerk for comfortable flight. That is good for a camera drone, but it makes the return after a gust slower. This is a likely explanation, not tested here (we did not vary ArduPilot's tuning).
  • Why no gain in constant wind: a steady push is cancelled by ArduPilot's inner velocity loop under every controller, so all four end at a similar small offset. PPO's training wind changed every 1–3 s, so its learned skill is the response to change.
