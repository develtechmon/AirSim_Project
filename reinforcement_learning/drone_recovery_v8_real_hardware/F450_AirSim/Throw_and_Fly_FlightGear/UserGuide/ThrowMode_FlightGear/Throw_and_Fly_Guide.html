THROWThrow & Fly: throw the drone, catch it
Outdoor with GPS (ArduPilot Throw mode) and indoor with optical flow (attitude-rule and PPO), watched in FlightGear

This guide turns your notes into a step-by-step run sheet. The throw is made inside ArduPilot's own simulator physics (-f quad) with a short push (SIM_SHOVE) and spin (SIM_TWIST). FlightGear only draws what the simulator does. Places where the notes needed a fix are marked FIX and listed in section 6.

The three rules that matter most. 1) Every run: motors on ≈ 0.3 s, otherwise the simulator is too slow and the numbers are not valid (section 5). 2) Same height source (POSZ) for every run you compare (section 4). 3) FlightGear and the simulator must start at the same place (C3).

1. How the pieces connect

Use ONE of the two FlightGear boxes. The script always talks to the simulator on tcp:127.0.0.1:5762; FlightGear never changes the test.
The simulator is the football match, throw_check.py is the goalkeeper, FlightGear is the TV. Changing the TV (WSL or Windows, KSFO or Kuching) does not change the match, unless the TV is so heavy that the match itself slows down (section 5).

2. What happens in one throw (script modes)

A goalkeeper (the script) watches the thrower's hand. The moment the ball leaves the hand (free fall), he dives (spool + recover). Once he has the ball (caught), he hands it to the referee (ArduPilot LOITER), who puts it down (LAND).

B1Rangefinder fix for rolling throws (once)WSL · simulator only

ArduPilot 4.4 SITL reports an infinite rangefinder distance when the drone tilts past 90°. Later code turns that into an integer and SITL stops with Floating point exception - aborting. The fix reports 99 m ("nothing in view") instead:

sed -i 's/        return INFINITY;/        return 99.0f;/' ~/ardupilot/libraries/SITL/SIM_Aircraft.cpp

cd ~/ardupilot

./waf copter

Check (one line = done):

grep -n "return 99.0f" ~/ardupilot/libraries/SITL/SIM_Aircraft.cpp
Only the simulator code changes. Your Stage 1–3 (AirSim, Gazebo) runs and real firmware are not affected.

C1. One-time setup

C1.1Install FlightGear 2024.1.7 (Windows 10/11)≈ 1.8 GB data download

From the FlightGear download page. Let the "Setup required data files" window reach 100%.

C1.2Copy ArduPilot's quad model to WindowsWSL · once

FlightGear has no ArduPilot quad. The arducopter model (props spin with the motor outputs, altitude/roll/pitch shown on screen) lives inside ArduPilot in WSL, so Windows FlightGear needs its own copy:

cp -r ~/ardupilot/Tools/autotest/aircraft /mnt/c/Users/lukas/fg_aircraft

ls /mnt/c/Users/lukas/fg_aircraft/arducopter

✅ Shows arducopter-set.xml, arducopter.xml, Models, quad.nas …

C1.3Make FlightGear_quad.batNotepad · once

Notepad → paste → Save As FlightGear_quad.bat (Desktop or project folder), Save as type: All files. The first time Windows Firewall asks, allow FlightGear on private and public networks.

@echo off
title FlightGear quad view (ArduPilot SITL)

rem ---- 1. Paths (change FG_EXE if your FlightGear is somewhere else) ----
set "FG_EXE=C:\Program Files\FlightGear 2024.1\bin\fgfs.exe"
set "FG_AIRCRAFT=%USERPROFILE%\fg_aircraft"

rem ---- 2. Check FlightGear is there ----
if not exist "%FG_EXE%" (
    echo [ERROR] fgfs.exe not found here:
    echo         %FG_EXE%
    echo FlightGear folders in Program Files:
    dir /b "C:\Program Files\FlightGear*"
    echo Fix the FG_EXE line at the top of this file.
    pause
    exit /b 1
)

rem ---- 3. Check the ArduPilot quad model is there ----
if not exist "%FG_AIRCRAFT%\arducopter\arducopter-set.xml" (
    echo [ERROR] ArduPilot quad model not found here:
    echo         %FG_AIRCRAFT%\arducopter
    echo Run this ONCE in WSL, then try again:
    echo   cp -r ~/ardupilot/Tools/autotest/aircraft /mnt/c/Users/lukas/fg_aircraft
    pause
    exit /b 1
)

rem ---- 4. Start FlightGear: listens on UDP 5503 for ArduPilot SITL ----
echo Starting FlightGear (KSFO, noon, quad) ...
"%FG_EXE%" --native-fdm=socket,in,10,,5503,udp --fdm=external --aircraft=arducopter "--fg-aircraft=%FG_AIRCRAFT%" --airport=KSFO --timeofday=noon --geometry=1400x900 --disable-sound --disable-ai-models --disable-random-objects --wind=0@0 --log-level=info

echo.
echo FlightGear closed (exit code %ERRORLEVEL%). Read any error above.
pause

--native-fdm=socket,in,10,,5503,udpDo not fly by yourself: listen on UDP 5503 for the drone's position from ArduPilot
--fdm=externalFlightGear physics off; ArduPilot's physics moves the drone

Paste this into Notepad, not PowerShell: PowerShell reads the commas in socket,in,10,,5503,udp as its own syntax ("Unexpected token").

Hover thrust must be rightWith MOT_THST_HOVER at its default 0.39, the F450 only balanced its weight in the catch and sank into the ground at 2 m/s (3/3 crashed). Real hover thrust 0.58–0.59 → 6/6 caughtMeasures the hover thrust before every launch and uses it for the rule, PPO and the height hold
