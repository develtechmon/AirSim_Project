The method, step by step

Like teaching a stunt pilot to recover from a spin: first a flight instructor (the attitude-rule teacher) flies 400 recoveries while a student watches and copies (BC). Then the student practises alone, small spins first, bigger ones only after passing (PPO + gated curriculum). Finally the plane gets a better rudder lock (yaw brake), which helps every pilot, and everyone is tested on the same set of spins.

0.4Start AirSim + ArduPilot SITL (WSL)≈ 2 min · before every step with Simulator = yes

Order: AirSim (Windows) → SITL (WSL) → script (PowerShell). Keep both windows open while the script runs.

1. Windows: start AirSim (your WindowsNoEditor build) and wait until the drone is shown.

2. WSL (Ubuntu terminal): start SITL from the GPS folder ~/sitl_gps, not from ~/ardupilot.

Why the folder matters: SITL saves its parameters (eeprom.bin) in the folder you start it from. ~/ardupilot holds the optical-flow setup; ~/sitl_gps holds the GPS setup used for Stages 1–3. Like two save files in a game: the folder decides which drone you load.

First time only (creates the GPS folder; SITL starts there with default parameters):

mkdir ~/sitl_gps

Every time:

cd ~/sitl_gps
sim_vehicle.py -v ArduCopter -f airsim-copter --console --map --sim-address=172.28.0.1 --out=127.0.0.1:14550

Restart AirSim after editing settings.json.

4. Finding: the yaw brake

What was wrong: after some HARD pitch flips the drone was level within ~0.3 s but kept spinning flat (up to 6.5 rad/s around the vertical axis, confirmed by the new r_rads log). The command asked for "the current heading", so ArduPilot braked that spin only weakly, and the recovery clock waited ~2 s. PPO cannot fix this: its outputs are roll, pitch and thrust only.

The fix: when nearly level, heading target = current heading − 0.5 s × yaw rate (max 0.8 rad). ArduPilot's own 400 Hz loop then stops the spin. Same code in SITL and on the Pi; spin-stop-fast and stock ArduPilot are not affected.

A figure skater lands a jump upright but keeps twirling until friction stops her. The yaw brake is dragging the toe on purpose.

Discussion points

  • Learned recovery vs ArduPilot: ~2× faster and +1.2 m on HARD flips; stock ArduPilot fails MEDIUM/HARD.
  • Interface matters: one change to the heading target halved recovery time for every attitude-based controller.
  • PPO vs teacher is close (+0.3 m, −0.07 s at n = 5): the 3d-1 test (n = 5 per cell, all types) decides how strongly this can be claimed.
  • BC made safe real-time training possible: PPO started from a network that recovered 54/54 hits.
  • SITL noise: fixed controllers varied up to ±1.7 m between runs on identical hits → compare within one run, report mean ± std.
