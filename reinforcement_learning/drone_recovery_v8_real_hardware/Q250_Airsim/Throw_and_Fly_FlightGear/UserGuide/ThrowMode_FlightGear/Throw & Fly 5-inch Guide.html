1. Brain and body: what each file is

A simulated drone needs two things, the same as the real one:

Brain: q250_throw.parmBody: q250.json
What it holdsArduPilot parameters: your tuned gains, hover value, motor curveThe physical drone: weight, size, motor strength, how hard it is to spin
Real-drone equivalentMission Planner → Full Parameter ListThe drone you hold in your hand
How it is loadedMAVProxy: param load (same as q250_sim.parm)Copied into ArduPilot's models folder once, then one extra part on the start line: --model quad:@ROMFS/models/q250.json
Same idea in AirSim—settings_Q250.json (MASS, ARM, THRUST …)
The parameters are the pilot, the JSON file is the aircraft. Your F450 tests put the right pilot into ArduPilot's default aircraft. This time the pilot gets your own aircraft.
Correction to the F450 guide. Without a JSON file, -f quad simulates ArduPilot's built-in generic quad (SITL source: 3.0 kg, 35 cm, hovers at 39 % throttle). The F450 throw results in that guide were made with that generic body, not an F450. Parameters cannot change the body; only the JSON file can.

2. How the pieces connect

The simulator is the football match, throw_check.py is the goalkeeper, FlightGear is the TV. The TV never changes the match, unless it is so heavy that the match slows down (that is what the timing check in B7 catches).

Take over, any time in the air

Lift buttons, not an accelerator: in PosHold (and AltHold) the throttle stick does not set motor power. It only says up / stay / down; the flight controller works out the power itself. So "my stick is not strong enough and it falls" cannot happen: a low stick only makes it go down slowly, under control. In Stabilize the stick is the power (an accelerator): never take over in Stabilize.
